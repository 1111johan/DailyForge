# 上线验收清单

## 数据库

- 重复调用每日任务接口两次，只得到同一条任务。
- 同时调用两个 Worker，只有一个领取目标任务。
- 将运行中任务的 `locked_at` 调整到 20 分钟前，可以被重新领取。
- 未配置产品知识或选题时，任务明确失败，不调用模型。

## 文案

- 合法 JSON 保存为一条 `generated_posts` 记录。
- 非 JSON 输出会自动请求修复，最多 2 次。
- 少于 3 个标题、少于 5 个标签或不是 4 张图片脚本时，不进入图片阶段。
- `selected_title` 不在候选标题中时校验失败。

## 图片

- 4 张图片严格按顺序生成，Storage 路径顺序正确。
- 第 3 张失败后重试，不重新生成前 2 张。
- 异步图片进入 `poll_image_1` 至 `poll_image_4`，轮询不消耗错误重试次数。
- 非图片、错误尺寸、小于 10 KB 或大于 20 MB 的文件不能进入飞书。

## 飞书

- 4 张图片在附件字段中可直接预览且顺序正确。
- 相同任务重复同步不会产生第二条记录。
- 飞书记录成功但本地更新失败后，重试能够找到原记录并完成。
- 自动检查有提示时，“生成状态”为“需要人工检查”。

## 自动化

- 每天 08:00（Asia/Shanghai）创建任务。
- Worker 每分钟调用一次，无任务时返回 `processed: false`。
- 连续 7 天每天仅生成一条预期内容。
- 401、字段错误、模型不存在等永久错误不会无限重试。
- 429、超时和 5xx 按 1、5、15 分钟退避。

## 回滚

1. 在 Supabase 中暂停两个 Cron 任务。
2. 保留数据库和 Storage 原始数据，不执行破坏性回滚。
3. 在 Vercel 回滚到上一部署。
4. 修复后手动推进失败任务，再恢复 Cron。
